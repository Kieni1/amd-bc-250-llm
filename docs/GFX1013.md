# Experimental GFX1013 compute-queue profile

The RPM ships an **opt-in, default-off** BC-250 GFX1013 lifecycle as package
profile `v0.2.1-alpha`. It is based on `DryhoppedIPA/bc250-gfx1013-fix`
`0.2.0-alpha` commit `d3e6dc062c34d2523db0abe5741d1f5b0dea00d9`.

This package profile deliberately enables only:

- the three pinned V33 kernel compute-queue lifecycle patches; and
- Mesa/RADV `0001-gfx1013-compute-queue-fix.patch` against Mesa `26.2.0-rc3`
  (`sha256:f733c005660d342a51c6727d1ad481f43d05b4c601ac72247fa641e1d73a8ad1`).

The optional upstream mesh/task patches, 40-CU changes, FSR changes, fan/power
policy and unrelated toolkit patches are not part of this profile. Current
upstream documentation disables the mesh/task additions because they can hang
the GPU; this LLM package therefore keeps the compute experiment narrow.

The package carries `PATCH-SHA256SUMS` plus `SOURCE-SHA256SUMS` under
`/usr/share/bc250-llm-server/gfx1013/upstream/`. `prepare` verifies both before
building. Downloaded exact-kernel SRPM and Mesa source identities, the exact
`kernel-devel` NEVRA/build-tree identity, built-module SHA-256, vermagic and
symbol-version ABI evidence, stock module/initramfs hashes, plus private RADV
library/ICD hashes are retained in root-only lifecycle state.

## Lifecycle

```bash
bc250 gfx1013 status
sudo bc250 gfx1013 prepare
# reboot the one-shot patched entry
bc250 gfx1013 status
sudo bc250 gfx1013 enable
sudo bc250 gfx1013 disable
```

`prepare` is exact-kernel. It requires the running kernel's build tree and
build dependencies, verifies that the resolved build tree is owned by the exact
`kernel-devel-$(uname -r)` RPM, downloads the matching Fedora kernel source RPM,
verifies that SRPM's exact VERSION-RELEASE, applies the V33 patches only after
dry-run, builds `amdgpu`, verifies vermagic and symbol-version ABI compatibility,
then builds the pinned Mesa source with the single accepted RADV patch.

The stock distro `amdgpu` file is used only transactionally while generating a
dedicated patched initramfs. It is restored byte-for-byte before `prepare`
continues, and the stock initramfs must remain unchanged. Interrupt/failure
cleanup restores the stock module and removes newly-created staged artifacts.

`prepare` refuses a non-stock module path, an ambiguous/missing stock BLS entry,
or a saved/default entry that is not the exact identified stock entry. It then
creates a dedicated `bc250-gfx1013-v33` BLS entry and sets it as **next boot
only**. The saved/default stock entry is not promoted or replaced.

`enable` is accepted only while actually booted through the marked patched
entry. It revalidates the package/source manifests, exact-kernel module hash,
vermagic/ABI evidence and private RADV, then checks the private ICD with
`vulkaninfo`. The Vulkan override is installed only as:

```text
/etc/systemd/system/ollama.service.d/70-bc250-gfx1013.conf
```

No global `/etc/environment` change is made and no user-wide systemd
environment generator is installed. A separate upstream GFX1013 installation
is treated as a conflict instead of being overwritten. If Ollama was already
active, it must restart successfully with private RADV before the patched boot
entry is promoted to the saved default. Activation is transactional: failures
remove the override and restore the previous stock saved/default entry.

`disable` first restores and verifies the recorded stock entry as both saved
**and next** boot. Only after that proof succeeds may it remove the Ollama
override, patched BLS/initramfs, private RADV and package lifecycle state. If
state is missing or invalid while risky package artifacts remain, it refuses to
clean up.

The same fail-closed rollback is called by `bc250 reset` and the RPM final-erase
`%preun`. Therefore package reset/erase is intentionally blocked if the stock
boot path cannot be restored and verified.

## Qualification boundary

The reference appliance kernel for this package profile is
`7.2.9-200.fc44.x86_64`. Other Fedora kernels are not silently reused: they
must build against their own exact running kernel tree and matching Fedora
kernel source RPM. The feature remains experimental/default-off even after it
builds successfully. Promotion to normal production use requires exact-device
A/B evidence for LLM inference plus clean stability/memory behavior.

Do not enable the private RADV half on a stock kernel. Upstream explicitly warns
that the Mesa compute-queue exposure depends on the repaired kernel lifecycle.
