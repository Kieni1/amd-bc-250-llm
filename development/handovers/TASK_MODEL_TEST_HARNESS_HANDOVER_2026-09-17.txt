# BC-250 Task-Model Test Harness Handover — 2026-09-17

## Purpose

This document records the reusable experimental method, scripting rules, evidence layout, acceptance logic, and command patterns for future BC-250 task-model work.

The goal is to avoid rebuilding the harness or repeating already-discovered mistakes.

---

## Core testing principle

### Reject cheaply, accept expensively

Use this funnel:

```text
candidate exists
    ↓
cheap raw/direct quality screen
    ↓
tiny warm-main survival probe
    ↓
small usefulness/robustness probe
    ↓
repeated canonical direct quality
    ↓
real Open WebUI task routing
    ↓
first-turn persistence/product lifecycle
    ↓
true concurrent overlap
    ↓
sustained stability
    ↓
promotion consideration
```

Never invert this order.

A large candidate should not get a 30–60 minute quality campaign before proving that a tiny load can coexist with the warm main model.

## Appliance lanes

Current service layout:

```text
main       127.0.0.1:11434
task       127.0.0.1:11435
agent      127.0.0.1:11436
embedding  127.0.0.1:11437
```

Foreground priority:

```text
prod-gpt-oss20b-ggml-org-mxfp4
```

The main model is intended to remain warm during normal background-task operation.

Do **not** set the main model to `keep_alive=0` merely to make a task candidate fit.

## Return-code convention

Recommended experiment semantics:

```text
0   = quality/acceptance pass with valid evidence
3   = quality fail with valid evidence
other nonzero = infrastructure / safety / restoration / archive failure
```

Priority when deriving final RC:

```text
restoration failure
> cleanup failure
> infrastructure/safety failure
> archive failure
> quality failure
> success
```

A quality failure must not abort evidence collection.

A global OOM/service-loss failure should stop subsequent expensive candidate arms.

## Shell safety rules

### Never kill the caller's interactive shell

Scripts should be executable children.

Use:

```bash
if [[ "${BASH_SOURCE[0]}" != "$0" ]]; then
    bash "${BASH_SOURCE[0]}" "$@"
    return $?
fi
```

Avoid dangerous top-level `set -e` behavior for evidence campaigns.

Prefer:

```bash
set -u
set -o pipefail
```

Then capture RCs deliberately.

### Interactive input

Never use plain `read` inside a here-doc-driven child where stdin may be the script source.

Use:

```bash
IFS= read -r -p "Paste chat UUID: " CHAT_ID </dev/tty
```

### Propagate child RC

A wrapper must return/exit with the child experiment's final RC.

Do not merely print it.

## Evidence hygiene

### Never archive credentials/session data

Do not archive:

- bearer tokens;
- raw session/auth responses;
- raw user/account objects;
- chat UUIDs unless absolutely necessary;
- emails/names/account IDs.

For browser-assisted persistence:

1. fetch raw data into `/tmp`;
2. extract only sanitized messages/tag names needed for evidence;
3. delete raw temporary objects;
4. scan the evidence tree for the active token;
5. archive only if the scan passes.

### Secret-scan failure

If the active token appears in evidence:

```text
DO NOT CREATE THE TARBALL
```

Keep the local evidence directory for manual remediation/redaction.

### No SHA/checksum generation

Experiment scripts should **not** generate `.sha256`, SHA sums, or other checksum sidecars.

This is intentional project policy.

## Always capture package/live contract before mutation

Before testing Open WebUI routing:

1. snapshot package desired state;
2. fetch live task config;
3. compare the package-owned task fields;
4. refuse to mutate if the appliance is already unexpectedly divergent.

Fields of interest:

```text
TASK_MODEL
TASK_MODEL_EXTERNAL
TASK_MODEL_PARAMS
TITLE_GENERATION_PROMPT_TEMPLATE
TAGS_GENERATION_PROMPT_TEMPLATE
QUERY_GENERATION_PROMPT_TEMPLATE
```

Only mutate the fields explicitly required by the experiment.

Afterward, restore the **exact original live config**, not a reconstructed approximation.

Then fetch it again and perform semantic JSON equality.

## Model-definition staging

Many active experimental models may exist only on `11434`.

That does **not** mean they should be excluded from cheap quality screening.

Recommended process:

### Phase A — quality screen on the lane where the model already exists

For example:

```bash
bc250-benchmark task exp-example-model \
  --ollama-url http://127.0.0.1:11434 \
  --output-dir "$OUT"
```

This is a quality-only test.

Do not claim coexistence from it.

### Phase B — only promising models are temporarily staged on the task lane

For a promising main-lane model:

1. query `/api/show`;
2. extract the generated Modelfile;
3. preserve:
   - GGUF/source;
   - template;
   - SYSTEM;
   - family;
   - quantization;
4. optionally replace only clearly justified task-role runtime parameters;
5. create a uniquely named temporary alias on `11435`;
6. verify the alias definition;
7. run the **tiny survival gate**;
8. delete only the temporary alias afterward.

### Parameter comparison

Ollama may reorder parameter lines.

Do not compare the raw multiline `parameters` string.

Normalize to key/value pairs and compare semantic content.

Example:

```python
def normalize_parameters(raw):
    pairs = []
    for line in str(raw or "").splitlines():
        line = line.strip()
        if not line:
            continue
        parts = line.split(None, 1)
        key = parts[0]
        value = parts[1].strip() if len(parts) > 1 else ""
        pairs.append((key, value))
    return tuple(sorted(pairs))
```

This fixes the false `definition parity` failure found during the first Qwen staging attempt.

## The tiny survival gate

This is now mandatory for any candidate substantially larger than the current task model.

### Preconditions

- all core services active;
- main GPT-OSS warm/resident;
- task lane does not already contain the candidate;
- no unexpected recent serious warning;
- package/live state known.

### Request

Use a trivial request:

```json
{
  "model": "<temporary-task-alias>",
  "prompt": "Reply with exactly: OK",
  "stream": false,
  "keep_alive": 0,
  "options": {
    "num_predict": 8
  }
}
```

### Sample resources before/during/after

At roughly 200 ms intervals capture:

```text
timestamp
MemAvailable MiB
swap used MiB
```

Swap **used** is:

```text
SwapTotal - SwapFree
```

Do not confuse `/proc/swaps` size with used swap.

### Minimum acceptance

Recommended guardrails:

```text
HTTP request succeeds
candidate unloads
main GPT-OSS remains resident
ollama.service active
ollama-task.service active
open-webui.service active
tika.service active
no new serious kernel warnings
MemAvailable >= 512 MiB
pre-request -> peak swap growth <= 512 MiB
```

These values are guardrails, not proof of final production quality.

Any global OOM is an immediate rejection for the concurrent task role.

### Serious warning regex

Use:

```text
out of memory|oom-kill|oom_reaper|killed process|device lost|gpu reset|amdgpu.*(reset|timeout|fault)|ring.*(timeout|reset|fault|error)
```

## Quality screen

### Canonical evaluator

Do not weaken it.

Use the package canonical six-case task screen for cheap comparison.

For current LFM, the observed reference envelope can be around:

```text
4/6 to 5/6
```

Therefore use opening/closing baseline as a **drift reference**, not an absolute rule that the opening baseline must always score >=5.

Example baseline stability concept:

```text
opening >=4/6
closing >=4/6
absolute opening/closing difference <=1
```

A challenger should generally show:

```text
>=5/6
```

before spending time on deployment work.

### Quality is not deployment

A model can score well while being unsafe.

Recent example:

```text
Qwen3 4B:
  5/6 quality
  catastrophic OOM as a concurrent task model
```

Keep these dimensions separate in reports.

## First-turn robustness corpus

Before repeated expensive qualification, test the failure shape that matters in the product.

Recommended minimum corpus:

```text
DE concise
DE rich
EN concise
EN rich
FR concise
FR rich
concept-dense
genuinely incoherent / General
```

For tags, Candidate C remains a useful diagnostic prompt.

A promising challenger should:

- preserve specific concepts;
- not collapse several obligations into one broad abstraction;
- pass concise French;
- not regress DE/EN relative to baseline;
- emit exactly one JSON object with exactly `tags`.

This corpus is **diagnostic**, not automatically release-gating unless adopted into package policy.

## Real Open WebUI quality

A finalist must be tested through the actual authenticated task endpoints.

Typical endpoints:

```text
/api/v1/tasks/title/completions
/api/v1/tasks/tags/completions
/api/v1/tasks/queries/completions
```

Every round should be complete.

For the canonical six-case live replay:

```text
cases == 6
```

Recommended reporting:

```text
canonical pass count
strict product-contract pass count
```

Strict product contract means:

- exactly one raw JSON object;
- exact expected key;
- no markdown;
- no explanatory prose;
- expected value shape.

Example:

```json
{"tags":["tag1","tag2","tag3"]}
```

not:

```json
{"tags":[...],"subtopic_tags":[...]}
```

## Persistence/product lifecycle

For automatic tags:

- test a completely new chat;
- first user turn must be self-contained;
- wait for first assistant completion and background tasks;
- do not send another message before capture;
- fetch the chat/tag state through the API;
- store only sanitized messages and tag names.

Known Open WebUI 0.11.3 lifecycle observation:

```text
tags appear to be generated after the first assistant turn
and did not refresh on the tested second turn
```

Therefore first-turn quality matters disproportionately.

API persistence is stronger evidence than whether visible tag chips are rendered in the UI.

## True overlap acceptance

Only run overlap after the candidate has passed:

```text
quality
survival
robustness
product-path routing
```

During overlap record:

```text
main HTTP request active
task HTTP request active
main model resident
task model resident
MemAvailable
swap used
task wall time
main wall time
```

Require actual temporal overlap and actual dual residency.

After the task:

```text
task candidate unloaded
main GPT-OSS still resident
no serious kernel warning
services healthy
```

Do not quietly re-warm the main model and call the candidate successful.

If main residency is lost, the candidate failed the coexistence test.

## Recovery check after an OOM experiment

Use the provided `task-appliance-recovery-check.sh`.

The desired state is:

```text
ollama.service       active
ollama-task.service  active
open-webui.service   active
tika.service         active

main lane:
  production GPT-OSS resident

task lane:
  empty

new serious warnings after recovery point:
  none
```

A recovered appliance is not evidence that the failed model was safe.

## Recommended campaign workflow for a future compact candidate

### Step 1 — cheap quality

```bash
MODEL='exp-new-compact-model'

bc250-benchmark task "$MODEL" \
  --ollama-url http://127.0.0.1:11434 \
  --output-dir "$HOME/task-screen-${MODEL}-$(date +%Y%m%d-%H%M%S)"
```

If it is clearly below the production reference, stop.

### Step 2 — create a temporary task alias

Use exact model/template/SYSTEM/quantization.

Use task-role parameters only if justified.

### Step 3 — survival

Run:

```bash
CANDIDATE_MODEL='tmp-task-example:latest' \
bash ./task-model-survival-template.sh
```

If survival fails, stop.

### Step 4 — concise usefulness

Run three self-contained DE/EN/FR first-turn tag cases.

If the candidate does not solve the target weakness, stop.

### Step 5 — repeated canonical

Use:

```text
baseline
candidate
candidate
candidate
baseline
```

### Step 6 — real product path

Run authenticated OWUI six-case rounds.

### Step 7 — first-turn persistence

Browser-assisted if necessary.

### Step 8 — true overlap

Only now spend the concurrency budget.

## Example resource sampler

```bash
printf 'timestamp\tMemAvailable_MiB\tswap_used_MiB\n'
while :; do
    mem="$(awk '/^MemAvailable:/ {print $2}' /proc/meminfo)"
    st="$(awk '/^SwapTotal:/ {print $2}' /proc/meminfo)"
    sf="$(awk '/^SwapFree:/ {print $2}' /proc/meminfo)"
    su=$((st-sf))

    awk \
      -v t="$(date +%s.%N)" \
      -v m="$mem" \
      -v s="$su" \
      'BEGIN {
         printf "%s\t%.2f\t%.2f\n", t, m/1024, s/1024
       }'

    sleep 0.20
done
```

## Example kernel safety check

```bash
SERIOUS_RE='out of memory|oom-kill|oom_reaper|killed process|device lost|gpu reset|amdgpu.*(reset|timeout|fault)|ring.*(timeout|reset|fault|error)'

journalctl -k -b --since "$TRIAL_START" --no-pager |
grep -Ein "$SERIOUS_RE" \
|| true
```

If this produces a new global OOM during candidate work, stop the campaign.

## Transfer pattern

Every evidence-producing script should print an rsync line.

Preferred pattern:

```bash
rsync -avz --progress \
  "$TARBALL" \
  "$STATUS_FILE" \
  '<review-user>@<review-host>:<review-path>/'
```

For several completed experiments:

```bash
rsync -avz --progress \
  ~/bc250-task-*.tar.gz \
  ~/bc250-task-*.tar.gz.status.txt \
  '<review-user>@<review-host>:<review-path>/'
```

Do not put secrets in filenames or transfer commands.

## Harness bugs already discovered — do not reintroduce

1. **Raw parameter-string equality**
   - Ollama can reorder parameter lines.
   - Compare semantic key/value content.

2. **Empty quality aggregate after infrastructure failure**
   - Do not run a quality aggregator merely because the directory exists.
   - Require actual run evidence.

3. **Baseline >=5 hard gate**
   - production reference can be 4/6–5/6.
   - use baseline as a drift envelope.

4. **Require task-lane registration before cheap quality screening**
   - main-lane models can be screened for quality first.
   - task staging comes only after quality survives.

5. **Continue after main model is killed**
   - never.
   - main-residency loss is a hard coexistence failure.

6. **Archive after failed token scan**
   - never.
   - withhold archive.

7. **Use `/proc/swaps` Size as Used**
   - wrong.
   - use `SwapTotal - SwapFree` or the correct Used column.

8. **Plain `read` inside here-doc child**
   - use `/dev/tty`.

9. **Visible tag chip as persistence truth**
   - use persisted API state.

10. **Checksum generation in experiment scripts**
    - do not generate SHA/checksum sidecars.
