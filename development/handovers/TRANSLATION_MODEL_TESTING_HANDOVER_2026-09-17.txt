# BC-250 Translation Model Testing Handover
## Status through Batch D3, 2026-09-17

### Scope and package boundary

Primary translation scope is **German ↔ French**. English is secondary and is not used for candidate ranking at this stage.

Current installed package boundary used by these tests:

- `bc250-llm-server 0.11.1-0.10.fc44`
- Treat `0.11.1-0.10.fc44` as belonging to the intended `0.11.1-0.10` package boundary.
- Do not require exact equality to `0.11.1-0.10`; Fedora/RPM distro suffixes such as `.fc44` are valid.

The task-model work is separate. The preferred task model remains the small LFM model with known caveats. Translation model selection is an independent workstream.

### Translation decision funnel

The current funnel is:

```text
short canonical DE↔FR screen
    -> harder DE↔FR discrimination corpus
    -> selected finalists only
    -> real Open WebUI/product-path translation
    -> resource/performance confirmation
    -> coexistence vs foreground deployment decision
```

Do not qualify every model completely before comparing the pool.

### Canonical short screen

The package's repaired DE↔FR office screen has 8 cases:

- DE→FR:
  - reference/date
  - invoice
  - negation
  - formal office
- FR→DE:
  - reference/date
  - lease
  - invoice
  - negation

This screen is now **saturated**: many strong candidates score 8/8. From this point onward, 8/8 means **advance**, not “models are equal.”

The short screen remains useful for:

- wrong target language
- source-language leakage
- semantic misses
- protected identifier/amount failures
- empty output
- output-budget exhaustion
- obvious formatting damage

### Stage 2A hard-corpus purpose

The next corpus has 14 DE↔FR cases designed to separate models that all score 8/8 on the canonical screen.

It targets:

- inclusive deadlines:
  - `bis`
  - `spätestens`
  - `au plus tard`
  - specifically reject overly strict `avant` where the date itself is allowed
- percentages:
  - `2 %`
  - `0,5 %`
  - maximum/cap semantics
- contractual modal scope:
  - only if
  - may / may not
  - prior written consent
- exact financial preservation:
  - CHF amounts
  - VAT percentages
  - references
- negation scope
- role/pronoun conditions
- paths, service names and configuration keys
- quoted text that must remain unchanged
- bullet-list preservation
- pipe-delimited table preservation

The Stage 2 score is decomposed into:

- target language
- semantic groups
- exact preservation
- source-language leakage
- target constraints
- formatting
- output-budget/thinking diagnostics

Do **not** collapse this to one overall number when reviewing failures.

### What is proven

- Translate-Gemma is the strongest small specialist observed so far.
- Hunyuan's remaining invoice issue is a real preservation failure.
- The default thinking behavior of several Qwen/GPT-style models can invalidate translation screening; explicit `think:false` is necessary for a fair direct-transform test when the runtime supports it.
- Ministral is a real survivor despite earlier historical expectations.
- Multiple 27B/35B Qwen models can match 8/8 short-screen quality, but with extremely low memory headroom.
- Large GPT-OSS variants do not currently justify their size for translation.
- The canonical 8-case benchmark is no longer sufficient to rank the leading models.

### What is NOT proven

- No current direct foreground result is a production-promotion decision.
- The latest large-model runs are **not coexistence qualification**.
- A foreground model passing alone does not prove it can coexist with warm GPT-OSS.
- Stage 2 harder-corpus quality has not yet been measured.
- The latest finalists have not yet been compared through the exact real Open WebUI translation product path.
- Deployment mode has not been decided:
  - concurrent translator, or
  - foreground translator that can unload/reload the main model.

### Recommended next actions

1. Run Stage 2A hard DE↔FR bundle.
2. Inspect every failed case manually; do not rely only on counts.
3. Reduce to roughly 2–3 finalists.
4. For finalists:
   - repeat/expand hard corpus if needed
   - compare latency and memory on short/paragraph/~1k-token inputs
5. Run exact real Open WebUI translation path.
6. Only then decide whether coexistence qualification is required or whether translation is an explicit foreground workload.
7. Do not promote from direct short-screen 8/8 alone.
