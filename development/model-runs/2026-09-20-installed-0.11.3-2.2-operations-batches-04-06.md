## Batch 05 — restore

### Configuration restore

Real configuration restore passed:

- restore refused to proceed while Open WebUI was still active;
- Open WebUI was stopped for the actual restore;
- restore completed successfully;
- pre-restore rollback material was created and its checksum/structure validated;
- rollback DB passed SQLite integrity checking;
- aggregate `uploads`, `vector_db`, and `cache` state remained unchanged;
- Open WebUI restarted successfully and office HTTP recovered;
- runtime topology and live 40-CU routing remained healthy;
- final authenticated `bc250-verify` returned `54 ok / 0 warn / 0 fail`.

### Identity restore defect

The production Open WebUI DB passed `PRAGMA integrity_check = ok` before identity restore, but already contained 142 rows from global `PRAGMA foreign_key_check`, observed in `knowledge_file` relationships unrelated to the selective identity subset.

The current `restore-users.sh` treated any non-empty post-restore global FK result as restore damage. As a result, a valid identity restore was rejected solely because the same unrelated pre-existing violations were still present.

The automatic rollback path then succeeded:

- pre-restore DB snapshot was restored;
- rollback checksum/integrity validation succeeded;
- Open WebUI restarted and HTTP recovered;
- runtime topology and 40-CU state remained healthy;
- final authenticated verifier returned `54 / 0 / 0`.

Required source correction: preserve strict `PRAGMA integrity_check`, capture and canonicalize the pre-restore FK violation set, compare the post-restore set by membership rather than count, and fail/rollback only if the identity restore introduces new FK violations. Pre-existing unrelated violations must not by themselves make the selective identity restore impossible.

The successful real rollback means there is no current need to invent an on-device failure-injection mechanism solely to prove rollback.

## Source consequences for 0.11.3-2.3

- keep the backup, configuration-restore, production/task runtime and rollback architecture unchanged;
- fix identity restore validation to compare canonical FK sets and detect only newly introduced violations;
- preserve the already-correct `DRY_RUN=1` safety while making actual/planned counters unambiguous;
- scripted generation runs should not display an interactive-looking board-note prompt when stdin is not a TTY;
- generation runtime/GPU-journal metadata should not appear as an empty pseudo-model in aggregates.
