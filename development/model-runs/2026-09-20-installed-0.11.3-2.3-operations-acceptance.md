## Maintenance UX

## Identity restore

The real Open WebUI DB still contained 142 global `foreign_key_check` rows unrelated to the package's
selective identity subset. Exact 2.3 identity restore reported:

```text
Integrity: OK
Baseline FK violations: 142
New FK violations: 0
Restore: successful
RC=0
```

The canonical pre/post FK-set SHA-256 values were identical, proving set equality rather than only
count equality. SQLite integrity remained strict and successful. Open WebUI restarted and final
appliance verification was clean.

The pre-restore safety guard also still refused identity restore while Open WebUI was active. Current
rollback material was created with a checksum sidecar and passed read-only SQLite validation.

A rollback DB file itself was observed as `root:root 0644`, but its entire rollback directory chain is
root-only/non-traversable and an unprivileged read failed. No effective data exposure was demonstrated.
A future trivial `0600` hardening is optional defense in depth, not a current security defect.

## Reboot acceptance

The supported operator path:

```text
sudo reboot
```

successfully reconstructed the appliance. After boot, SSH, office HTTP, normal main/task/embedding
topology, maintenance configuration/timers, firewalld and live 40/40 CU routing returned; zero failed
units remained, `rpm -V` stayed clean and the authenticated verifier returned 54/0/0.

Do not deliberately repeat the previously reproduced unreliable `sudo systemctl reboot` path merely
for acceptance. Its deeper root cause remains unproven.

## Remaining source defect: pinned live-manager CPU-unlock reboot

Installed-package inspection found one remaining executable `systemctl reboot` in
`/usr/bin/bc250-cu-live-manager`, in the interactive CPU-core-unlock reboot prompt. The package pins
upstream live-manager commit `a929085d791f126ce76a60eb609610820fb08066`; that source contains an
interactive `offer_cpu_unlock_reboot()` branch which calls:

```text
systemctl reboot
```

when the operator explicitly answers yes. `--yes` remains non-rebooting and only tells the operator
to reboot when ready.

The next source revision should patch only that reachable interactive path to `/usr/sbin/reboot`,
using the package's existing live-manager patch rather than introducing a reboot framework or copying
the upstream source into the repository.

## Other observations not classified as defects
