## Interpretation

This was an **implementation defect in the restoration probe**, not a RAG-quality failure. The generic loader correctly fell back from `/api/generate` for an embedding-only model, but supplied an empty `/api/embed` input that Ollama 0.34 rejects. The harness was correct to fail closed because benchmark success is not sufficient if normal appliance state cannot be restored.

Release 1.5 fixes only the probe payload by using a harmless non-empty embedding input while continuing to omit an explicit keep-alive so the embedding lane's normal policy applies.

The `tags-en` relevance miss remains a separate model-quality/evaluator observation. Do not change the task prompt or evaluator solely from this partial run; inspect/retest it independently.
