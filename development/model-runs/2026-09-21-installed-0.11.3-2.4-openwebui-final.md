# Installed 0.11.3-2.4 Open WebUI final investigation

## Evidence class

Operator-supplied device acceptance for exact installed:

```text
bc250-llm-server-0.11.3-2.4.fc44.x86_64
```

The final combined temporary desired-state contract test returned `RC=0` and restored all temporary
state. The raw device archive was not independently inspected in the source integration environment.

## Confirmed package defects

### Ordinary-user model authorization

Package-created Open WebUI model rows had empty `access_grants`. Administrator use worked, but an
ordinary `user` account could not use the curated roles. Device attribution showed the production
contract requires authenticated read access on exactly twelve active package-owned rows:

```text
bc250-office-standard
bc250-office-documents
bc250-office-translation-de-fr
bc250-office-translation-fr-de
bc250-office-advanced
bc250-office-deep-reasoning
prod-gemma4-e2b-unsloth-qat-ud-q4-k-xl:latest
prod-gemma4-e4b-unsloth-qat-ud-q4-k-xl:latest
prod-translate-gemma4-sub-e4b-17s-q4-k-xl:latest
prod-qwen35-9b-unsloth-q6-k:latest
prod-gpt-oss20b-ggml-org-mxfp4:latest
task-lfm25-1.2b-instruct-liquidai-q6-k:latest
```

Required grant:

```text
user:*:read
```

The five production base rows plus task row remain `meta.hidden=true`. The inactive legacy
`bc250-office-translation` row is not part of the production contract.

The tested security boundary remained intact: one ordinary user could not retrieve another user's
private document directly or through a valid Documents RAG request after model read access was
applied. Hidden implementation rows are selector-hidden, not API-forbidden to an authenticated client
that already knows a canonical ID.

### Deep Reasoning residency / memory safety

With normal long residency, `bc250-office-deep-reasoning` left GPT-OSS resident at roughly
1.5–1.7 GiB MemAvailable. A following title/tag request cold-loaded the approximately 1 GiB task
model and reproduced global memory pressure with kernel OOM termination of Open WebUI, Tika and
user-session processes.

Device testing proved the narrow package mitigation:

```text
bc250-office-deep-reasoning.params.keep_alive = 0
```

Preset-level `keep_alive=0` unloaded GPT-OSS immediately after the Deep response, recovered roughly
11.5 GiB MemAvailable before the task request, and allowed both title and tag generation to return
HTTP 200 with no new OOM/allocation/GPU-reset event. Standard and Advanced do not need residency
changes based on current evidence.

### Desired-state verifier representation

Status compared every package `models.json` row against `/api/v1/models/export`. Exact OWUI v0.11.3
represents curated presets there, but base-model overrides (`base_model_id == null`) are exposed in
`/api/v1/models/base` and direct per-ID lookup. The six hidden implementation/task rows therefore
existed and worked while status falsely reported them missing.

Required status contract:

```text
base_model_id != null  -> /api/v1/models/export
base_model_id == null  -> /api/v1/models/base
```

No model import/apply redesign is required for this defect.

## Closed findings

Arena/local-offline/upload policy, hidden model state, curated role generation, translation, Documents
RAG, broader realistic document lifecycle, moderate PDF/DOCX/XLSX/PPTX Tika extraction,
exclusive-agent topology and nested `options.num_predict` cap behavior were reported healthy. The
pinned v0.11.3 OpenAI-style adapter limitations around root `max_tokens`, reasoning-token accounting
and `finish_reason` remain documented compatibility boundaries, not new package fixes.
