## Release scope reviewed

The source release contains the three device-motivated Open WebUI corrections:

1. minimum-required/additive `user:*:read` convergence on the exact twelve active production model
   records, while preserving unrelated grants and leaving the inactive legacy translation row outside
   the production contract;
2. `bc250-office-deep-reasoning.params.keep_alive=0`, without changing Standard/Advanced residency;
3. two-view desired-state inspection (`/api/v1/models/export` for curated presets and
   `/api/v1/models/base` for base-model overrides), with narrow response-shape guarding and accurate
   diagnostics.

Release hardening also corrects the live-manager provenance notice and adds a pre-build gate that
requires the carried patch to dry-run/apply against the exact prepared pinned source before RPM
preparation.

## Build-path audit

The project build ownership remains unchanged:

- `make validate` runs shell syntax, repository/RPM preflight and the deterministic Python suite;
- `make sources` prepares the pinned third-party cache and now validates the carried live-manager
  patch/provenance;
- `make sources-check` verifies existing source-cache integrity and repeats patch/provenance validation;
- `make source-tar` creates reproducible Source0;
- `make rpm` depends on the prepared sources, Source0 and deterministic validation, then runs
  `rpmbuild -ba` and checks the resulting binary payload;
- GitHub CI performs the authoritative build inside Fedora 44 and additionally runs Ruff and
  ShellCheck.

## External-source / RPM gate still pending

This source environment is not the authoritative Fedora builder and currently lacks `rpmbuild`,
`rpm`, `cargo`, `ruff`, `shellcheck`, Podman and Docker. Its `sources/` cache is empty. Therefore:

- `make sources-check` correctly fails because the four required pinned source/vendor archives are
  absent;
- `make sources` cannot populate them here because shell-network DNS cannot resolve `github.com`;
- the new live-manager checker has deterministic unit coverage and the patch hunk contexts were
  compared with the public exact `a929085d791f126ce76a60eb609610820fb08066` source, but the required
  full cached-archive dry-run/apply remains an authoritative build gate;
- Ruff, ShellCheck, SRPM/RPM construction and RPM payload inspection are not claimed from this
  environment.

These are environment/evidence boundaries, not source-test failures. The Fedora 44 build must supply
the pinned sources and pass `make rpm` before release artifacts are considered built.
